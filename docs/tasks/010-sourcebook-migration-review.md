# 작업 010 — 설정집 이관 제안과 일괄 검토

상태는 요구사항 정리다. 설정집 실증에서 원문 여러 건을 읽고 고정 출처 참조가 있는 초안을 만들 수 있었다. MCP에서 새 요소의 타입은 일반 문서로 고정되고, 작업 본문에는 마지막 제안의 내용이 표시된다. 가져오기 확장자와 MCP 활동 중복 수정은 독립된 회귀 작업이다.

## 타입을 지정한 제안

- 에이전트가 프로젝트의 지원 종류를 확인하고 인물·장소·장면·규칙 등의 새 초안에 종류를 명시할 수 있다. 종류와 메타데이터는 현재 스키마 잠금과 확장 계약으로 검증한다.
- 제안은 출처 문서의 고정 리비전을 참조한다. 하나의 원문에서 여러 초안을 만들거나 여러 출처를 한 초안에 연결할 수 있다. 모순·미정·미채택은 검토에 드러나며 확정된 값으로 채우지 않는다.
- 종류가 지원되지 않거나 필수 필드가 없으면 실패 이유를 해당 제안에 표시한다. 작업 기준과 사용자 승인 경로는 기존 계약을 따른다.

인수 시나리오에서는 합성 원문의 인물·장소·규칙을 서로 다른 종류로 제안하고, 고정 출처와 미기록 값을 확인한다. 미지원 종류나 확장에 대한 진단과 유효한 다른 제안의 보존도 확인한다.

## 설정집 단위 검토

- 원문 목록에서 가져온 파일, 연결된 제안, 검사 결과와 검토 상태를 확인한다. 한 원문에서 여러 제안이 나왔을 때 각 리비전과 변경 내용을 열 수 있다.
- 처리 중단 후 체크포인트에서 이어갈 때 완료한 원문과 아직 처리할 원문을 식별한다. 이번 실행에서 발견한 가져오기 오류는 경로와 함께 남긴다.
- 가져온 원문과 생성된 제안의 대응을 한곳에서 검토한다. 사용자 승인과 통합은 검토 대상 커밋·diff에 연결한다.

인수 시나리오에서는 세 원문을 이관하고 일부 성공 후 실행을 중단한다. 이어서 진행했을 때 기존 제안이 중복 생성되지 않고, 마지막 제안을 열기 전에도 앞선 제안의 출처·본문·진단을 확인할 수 있어야 한다.

## 별도 판단 항목

- 원문에 해당 타입의 확장이 없으면 누가 새 확장과 기본값을 정할지 결정해야 한다.
- 검토할 단위와 통합 범위를 정해야 한다. 기준에는 개별 제안, 출처 문서, 전체 묶음이 있다.
- 원문 패키지의 JSON과 큰 PNG는 원래 파일로 보존할 수 있다. JSON 자동 구조화와 256 KiB를 넘는 PNG의 관리 첨부 방식은 별도 요구로 검토한다.
