# 작업 011 — 설정집 작업 흐름 성능

상태는 머지 후 착수다. 제공된 소설 패키지로 인물 초안 6건, 인물 간 고정 참조 5건, 원본 PNG 6장을 생성하고 Chrome에서 확인했다. 이 흐름을 사용자 개입 없이 검토 단계까지 실행할 수 있지만 실제 작업에서 제안 저장과 통합 diff 준비를 기다리는 시간이 길었다. 모델 응답 시간과 CRAFT 처리 시간은 분리해 측정한다.

## 1. 기준 측정

- 같은 소설 패키지는 로컬에서 재현한다. 자동 회귀에는 문서, 참조, 원본 PNG의 수와 크기가 비슷한 합성 fixture를 사용한다. 가져오기, 작업 열기, MCP 문서 조회·초안 저장, 통합 diff 준비, 통합 적용, 첫 이미지 표시 각각의 시간과 최대 메모리를 측정한다.
- 최초 실행과 반복 실행을 구분한다. 단계별 파일 열거·읽기·해시 횟수, Git 호출 수, 작업 잠금 대기와 `WORKTREE_BUSY` 빈도를 기록하고 사용자 대기 비용이 큰 경로부터 개선한다.
- 1,000요소·10,000리비전 규모는 기존 `npm run bench:index`로 함께 확인한다. 단계 9의 작업 폴더 exact p95는 12.01초, 한 파일 증분 점검은 14.57초였다. 목표는 각각 0.20초와 1초이며, 전체 재구축은 당시 13.63초였다. [측정 조건](009-release-acceptance.md#성능-재현).

## 2. 병목 개선

- 먼저 MCP 호출과 제안 저장에서 같은 worktree와 Git 스냅샷을 반복해서 확인하는 비용을 줄인다. 기준 커밋으로 식별되는 결과를 재사용하고, 작업 파일 변경을 감지하면 해당 검증을 갱신한다.
- 이어서 통합 diff 준비·적용과 PNG 로딩을 측정한다. 이미 확인한 불변 Git 객체의 재사용, 통합 후보를 만드는 중복 읽기 감소, 이미지 바이트 전달 비용을 실측 순서에 맞춰 검토한다.

## 인수 기준

- 같은 자료로 변경 전후의 시간과 메모리를 비교한다. 개선 효과와 남은 병목을 단계별로 기록한다.
- 빠른 조회에서도 외부 편집과 파일 교체가 감지되고, 검토 토큰은 해당 커밋과 diff에 결속된다. 고정 참조, 원본 PNG의 SHA-256, 중단·복구 동작을 기존 회귀와 같은 설정집 실증으로 확인한다.
- 성능 개선 이후 [설정집 단위 검토](010-sourcebook-migration-review.md#설정집-단위-검토)를 진행한다.
