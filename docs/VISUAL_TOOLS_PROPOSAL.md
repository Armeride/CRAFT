# 이미지 생성과 문서 시각화 검토

2026-11-19 검토안. 구현 순서와 후보를 제안한다.

사용자가 요청한 범위는 Codex 이미지 생성, OpenAI 호환 이미지 엔드포인트 등록, 작업 중 만든 결과의 문서 연계, 시퀀스 등 시각화 도구의 연결과 결과 관리다. 공통 작업 흐름은 **요청 → 생성 또는 렌더링 → 미리보기 → 문서에 첨부 → 검토·보존**이다. 이미지 모델과 도식 렌더러는 각자의 입력과 결과 형식을 사용하고, 생성 이후의 저장과 검토 규칙을 공유한다.

| 요청 | 평가와 권장 배치 |
|---|---|
| Codex 이미지 생성 | 인물 콘셉트, 지역 삽화, 아이템 이미지처럼 시각적 해석이 필요한 소재에 적합하다. **7단계 후속 작업**에서 CRAFT가 실행한 Codex의 지원 여부와 이미지 이벤트를 확인하고, 결과를 첨부 후보로 가져온다. |
| OpenAI 호환 이미지 API 등록 | Codex와 독립적으로 서비스·모델을 선택할 수 있다. **7단계 후속 작업**에서 이미지 API용 연결 유형을 추가한다. 단계 7의 프로필, 자격 증명 참조, 외부 요청 상태 기록을 재사용한다. |
| 작업 중 이미지 생성·관리 | 공급자와 관계없이 필요한 기능이다. **7단계 본체**에서 정적 PNG로 검증·미리보기·첨부·체크포인트 복원을 구현했다. 실제 생성 결과에 대한 사용자 검토와 문서 반영은 이어지는 이미지 작업으로 확인한다. |
| 시퀀스·기타 시각화 | **8단계**에서 장면·사건 시퀀스와 게임 조건 흐름을 원본 데이터에서 그린다. **10단계 선택 확장**에서 고급 편집·내보내기와 추가 렌더러·외부 도구를 검토한다. |

## 7단계 본체 · 결과를 문서와 함께 보존

7단계에서 해시 경로, PNG와 초안 링크의 저장, 웹 미리보기, 작업 브랜치 복원, 문서와 함께 승인 통합을 검증했다. 아래 항목은 생성 결과를 연결할 때 검토할 사항이다. [작업 007](tasks/007-resume-skills-mcp.md).

- 생성 결과는 해당 작업 공간의 후보로 표시한다. 사용자가 선택해 첨부하면 문서 리비전은 자산의 안정적인 ID 또는 경로와 콘텐츠 해시를 참조한다. 교체는 새 자산을 만들며 이전 리비전에 연결된 파일도 열 수 있다. 제목·캡션·대체 텍스트를 편집할 수 있게 한다.
- 검토 화면에서 본문 차이와 함께 첨부 추가·교체·제거를 이미지 미리보기로 표시한다. 승인된 첨부와 이를 참조하는 문서를 같은 변경 묶음으로 통합한다. 체크포인트와 새 checkout에서 서비스 세션이나 임시 URL 없이 승인된 파일을 복원한다.
- 최초 대상으로 PNG/JPEG/WebP 등 정적 이미지를 검토한다. 실제 파일 형식·크기·픽셀 수와 프로젝트 경로를 검증하고, 화면은 CRAFT가 바인딩한 작업 공간에서 파일을 읽는다. 출처에는 공급자·모델·시각·결과 해시를 남긴다. 생성 지시와 입력 원문은 로컬 작업 기록에 둘 범위를 별도로 정한다.
- 기존 공개 v1 형식을 기준으로 참조 방식과 구버전 읽기 동작을 검증한다. 리비전 메타데이터에 새 구조가 필요하면 명시 버전의 확장 계약을 검토한다. 파일별·프로젝트별 용량 한도, 대형 바이너리의 Git LFS, 후보 정리 정책은 실측 후 결정한다.

## 7단계 후속 작업 · 실제 이미지 공급자

두 경로를 같은 첨부 흐름에 연결하는 별도 작업을 권장한다. 7단계 본체의 재개·스킬·외부 MCP 인수 범위를 유지할 수 있도록 모델 없는 자산 복원 검증과 실제 공급자 시험을 각각 기록한다.

- **Codex 내장 경로.** 공식 문서에 Codex의 내장 이미지 생성이 있다. 단계 6에서 생성한 App Server 스키마에도 `imageGeneration` capability와 이미지 완료 항목의 `savedPath` 등이 있다. CRAFT의 현재 어댑터는 이미지 항목을 수집하지 않는다. 실제 설치 버전·계정·실행 정책에서 사용할 수 있는지 확인한 뒤, 승인된 실행의 구조화 이벤트와 결과를 바인딩한다. 파일 경로가 있으면 해당 실행이 만든 파일만 복사하고, 인라인 결과가 오면 전송·저장 크기 한도를 검증한다. 내장 도구 사용량은 Codex 쪽에 귀속되며, API 연결은 사용자가 선택한다. [Codex 이미지 생성](https://learn.chatgpt.com/docs/image-generation)
- **OpenAI 호환 API 경로.** 설정에서 이름, HTTP 서비스 주소, 모델 ID, 로컬 자격 증명 참조를 저장한다. 초기 호환 범위는 `POST /v1/images/generations`의 단일 정적 이미지 생성이다. `b64_json`을 우선 검증하고 URL 응답은 연결 정책이 허용한 주소에서만 크기 제한을 적용해 로컬 파일로 가져온다. 생성 옵션과 응답 형식은 공급자별로 시험한다. 편집, 스트리밍, 비동기 작업 조회는 각각 호환 범위가 확인된 뒤 추가한다. [OpenAI 이미지 생성 API](https://developers.openai.com/api/reference/resources/images/methods/generate)
- **실행과 복원.** 최초 실행 전에 공급자와 전송할 프롬프트·선택한 참조 자료를 보여준다. 프로젝트에는 연결 이름과 작업 식별자를 기록하고 자격 증명 원문은 로컬 자격 증명 저장소에서 관리한다. 취소·타임아웃 후 공급자의 실제 완료 여부가 불명확하면 작업 상태를 보존하고 자동 재전송을 막는다. 동일 요청과 이미 보존된 결과를 연결해 중복 첨부를 방지한다.

## 8단계 · 원본 데이터를 그리는 시각화

소설에서는 독자가 읽는 장면 순서와 세계 안에서 사건이 발생한 순서를 전환해 볼 수 있는 타임라인을 우선한다. 회상 장면처럼 순서가 다른 경우 각 기준에서 같은 장면의 위치를 확인할 수 있어야 한다. 게임에서는 퀘스트 조건, 입력 사건, 상태 변화의 흐름이나 참여자 간 메시지 순서를 표시한다. 시점·관점·기준·가정은 기존 조회 서비스가 결정하며 도식에서 근거 리비전으로 이동할 수 있게 한다.

- **조회에서 자동으로 그리는 도식**은 고정된 리비전과 조회 입력으로 재생성한다. 입력이 바뀌면 다시 계산하고, 문서에 보존한 도식에는 원본 기준과 렌더러 버전을 기록한다.
- **사용자나 AI가 작성한 설명 도식**은 도식 원문을 편집 가능한 형태로 보존하고, 화면에서 로컬 렌더링한다. Mermaid를 시퀀스·흐름·상태 도식 후보로 두고 고정 버전, 입력 규모 한도, 외부 링크·HTML·스크립트 제한, 텍스트 대체 보기를 시험한 뒤 채택을 결정한다. 같은 자산 관리 화면에서 렌더링 결과와 원문을 찾을 수 있다. [Mermaid 시퀀스 다이어그램](https://mermaid.js.org/syntax/sequenceDiagram.html)
- 관계 그래프의 기존 엔진 교체 흐름은 유지한다. 장면 타임라인과 퀘스트 흐름에 필요한 입력을 각 조회에서 받아 렌더러로 전달하며 다른 렌더러는 동일한 문서 첨부·검토 계약으로 추가한다.

## 검증 기준과 미결정

- **7단계 본체:** 모델 없는 이미지로 요청, 미리보기, 첨부, 체크포인트 및 문서 복원을 검증한다. 다른 작업 공간의 파일이나 미승인 결과가 원본 프로젝트에 들어가지 않는지 확인한다.
- **7단계 후속:** Codex와 호환 API별 결과를 1개씩 문서에 첨부하고, 교체한 뒤 이전 리비전과 새 리비전에서 각각 열리는지 검증한다. 미지원, 인증 오류, 잘못된 응답, 타임아웃, 중복 요청도 확인한다. 비용이 발생하는 호출은 별도 동의 범위에서 시험한다.
- **8단계:** 회상 장면 한 건과 조건부 퀘스트 한 건으로 세계 시간/독자 순서 및 가정별 분기를 검증한다. 관점에서 보이지 않는 사건과 제목이 도식에도 표시되지 않는지 확인한다.
- **9단계:** 실제 바이너리가 포함된 clone, 대상 리비전 충돌, 자산 누락, 손상, 앱 재시작 복구, 저장소 크기 증가를 검증한다.
- **미결정:** 첫 호환 API 공급자·모델, Codex 내장 지원 버전 범위, 렌더러와 정확한 버전, 용량과 보존 한도다. 앱 전체 요구사항 번호와 필수 인수 기준 편입은 범위 확정 후 업데이트한다.
