# 시점·상태·관점 조회

상단의 **시점과 상태**에서 상태 비교, 장면과 관점, 게임 규칙과 관찰을 엽니다. 상단에서 기준 묶음을 고릅니다. 여러 플랫폼이나 모드가 후보이면 해당 값을 입력하고 **범위 적용**을 누릅니다. 작업을 열어 둔 경우 프로젝트 자료, 작업 시작 기준, 작업 파일의 조회를 선택할 수 있습니다.

## 상태 비교

1. **상태 비교**에서 요소를 고르고 비교 A·B에 장면 경계 또는 작중 시간 눈금을 입력합니다. 장면 결과는 그 장면의 채택 리비전과 기록한 세계 시간을 사용합니다.
2. **확정**은 선택된 정본 발생 기록 중 승인과 유효한 검토가 있는 사건을 적용합니다. **작업 중 포함**은 채택된 초안 사건도 평가하고 그 효과를 잠정으로 표시합니다. 검토 전 초기값은 잠정이며 기록이 빠졌으면 미기록 또는 불명으로 표시합니다.
3. **상태 비교 실행**으로 값 차이, 각 조건의 판정, 사건 순서와 근거를 확인합니다. 초기값과 변경에 사용한 리비전은 **출처**·**근거**에서 열 수 있습니다.

게임에서는 **가정 시나리오**를 고른 뒤 비교 A·B 각각에 입력 사건을 선택합니다. 예를 들어 A에 `enter_player`, B에 `enter_npc`를 넣습니다. 개체 선택은 표시 범위를 바꾸고, 입력 사건 선택이 계산 경로를 바꿉니다. **개체별 가정 값**에는 `{"player":{"level":9}}`와 같은 JSON을 넣어 별개로 계산할 수 있습니다. `false`와 미기록은 서로 다른 결과입니다. 가정을 저장하려면 기존 수동 편집 흐름에서 시나리오의 새 리비전을 작성합니다.

## 장면과 관점

**장면과 관점**에서 원고 순서, 장면, 이전·이후 경계를 고릅니다. 작가 화면은 작중 시간과 독자에게 보여 준 순서를 따로 표시합니다. 인물을 지정하면 시간 불변 설정, 시점 상태, 알고 있음·믿음·의심·명시적 무지·미기록을 확인할 수 있습니다.

독자 결과는 그 원고 경계까지 기록한 공개 문장입니다. 인물 결과는 인식 사건 본문에서 작가가 작성한 표현을 사용합니다. 작가 초안에 비밀을 적을 때는 해당 인물에게 제공할 문장과 구분해서 작성합니다. **이 관점에서 공개된 표현 검색**은 이 결과 범위에서 검색합니다.

확정 관점에서 **관점 제한 Claude 작업**을 시작할 수 있습니다. 작업 시작 Git 기준에 묶인 공개 문장과 전용 읽기 도구만 Claude에 전달합니다. 새 임시 폴더에서 파일·셸 도구를 제한하고, 응답을 작업 기록에 보존합니다. 일반 AI 실행과 왼쪽 탐색은 작가용입니다. 제한 프로필은 공급자에게 제공되는 도구 및 데이터의 경계입니다. 운영체제에서 실행 파일 자체를 격리하는 프로필이 필요한 경우에는 별도 실행 환경이 필요합니다.

## 게임 규칙과 빌드 관찰

**게임 규칙과 관찰**에서 기준과 범위의 채택 규칙, 미채택 리비전, 빌드 관찰을 각각 확인합니다. 단위·허용 범위, 규칙 결정·근거, 관찰 빌드·조건·측정 시점이 표시됩니다. 관찰이 가리킨 정확한 채택 리비전에 같은 단위의 값이 있을 때 차이를 계산합니다. 기존 요소의 **리비전 비교**에서 두 리비전의 속성, 본문, 참조 차이를 볼 수 있습니다.

## 명령과 자동 조회

`npm run index -- state-evaluate --app-data <폴더> --registration <등록 ID> --query <JSON 파일>`로 `{"worldTick":50,"mode":"confirmed"}` 같은 요청을 조회할 수 있습니다. `state-compare`의 JSON에는 같은 구조의 `before`와 `after`를 둡니다. 직접 시간 대신 `{"scene":{"sequenceId":"seq_border","sceneId":"ent_border_chapter_one","boundary":"after"}}`로 장면 경계를 선택할 수 있습니다. 기존 작업의 경우 등록 ID 대신 `--run <ID> --view basis` 또는 `--view working`을 사용합니다. `story`와 `game`도 같은 명령으로 조회합니다.

일반 AI 작업에는 `state.evaluate`, `state.compare`, `narrative.context`, `game.context` 조회 도구가 제공됩니다. 결과를 보존할 때 입력·자료·결과 해시가 함께 기록됩니다.

## 예시 열기

실행 중인 미리보기가 있다면 다른 포트를 지정할 수 있습니다. 각 예시의 작업 공간은 별도 경로에 보존됩니다.

```powershell
npm run ui:preview -- --example border-story --port 4176
npm run ui:preview -- --example narrative --port 4177
npm run ui:preview -- --example game-design --port 4178
```

- **국경** · 상태 비교에서 `국경 지역`을 고르고 1장과 5장 이후를 비교합니다.
- **소설** · 독자 관점에서 첫 장면 이전에는 통로 공개가 없습니다. 독자 순서 두 번째의 회상은 작중 시간이 더 이르지만 첫 장면의 공개를 포함합니다.
- **게임** · PC PvE 회피 규칙의 0.2초와 빌드 관찰의 0.25초를 확인합니다. 플레이어와 NPC의 조건부 문 열기는 기본 예시 또는 `border-story`의 상태 비교에 있습니다.
