# 로컬 설치, 업데이트와 복구

## 설치와 실행

Git, Node.js 24.21.0과 npm 11.19.0이 필요하다. 소스 checkout에서 `npm ci`, `npm run build`, `npm run ui:build`, `npm start`를 차례로 실행한다. 브라우저에서 `http://127.0.0.1:4173`을 열고 Git 저장소의 최상위 폴더를 등록한다. `npm start -- --app-data <별도-경로> --port 4174`로 앱 데이터와 포트를 선택할 수 있다. 앱 데이터 경로는 프로젝트 저장소 밖에 둔다. 기본은 Windows의 `%LOCALAPPDATA%\CRAFT`, Linux의 `$XDG_DATA_HOME/CRAFT` 또는 `~/.local/share/CRAFT`다. 이전 미리보기에서 시작한 작업은 `npm run ui:preview`로 다시 열 수 있으며, 기존 앱 데이터를 그대로 사용하려면 `--app-data`에 미리보기의 `app-data` 경로를 지정한다.

실행기를 쓰려면 선택한 공급자를 별도로 설치하고 그 공급자에서 로그인한다. 버전, 인증, 시작, 중단, 체크포인트 확인은 [실행기 사용 안내](AGENT_WORKFLOW.md)를 따른다. 모델 없이 수동 편집·검토와 로컬 테스트 실행기를 사용할 수 있다.

## 업데이트와 스키마

1. 실행 중인 작업을 멈추고 체크포인트를 남긴다. 중단된 통합이나 저장이 있으면 복구 화면에서 상태를 확인한다. 브라우저에만 남은 편집을 저장하고 서버를 종료한다.
2. 아래 절차로 백업한다. CRAFT 소스 checkout을 새 버전으로 업데이트하고 그 버전의 Node/npm으로 `npm ci`, `npm run build`, `npm run ui:build`를 실행한다. 네이티브 모듈은 사용할 OS에서 설치한다.
3. 같은 데이터 경로로 다시 시작하고 대표 프로젝트의 채택 기준과 작업 목록을 확인한다. `npm run migration -- support`로 설치된 앱의 변환 지원 범위를 확인한다.

| 형식 | 읽기·쓰기와 변환 |
|---|---|
| Core 1 | 읽기·쓰기. 현재 버전으로 마이그레이션하면 no-op |
| `narrative@1`, `game_design@1`, `state_model@1` | 앱 계약과 프로젝트 스키마 잠금이 일치하면 읽기·쓰기 |
| 사용자 확장 | 잠근 JSON Schema와 선언한 참조에 한해 읽기·검증. 필수 해석기가 없으면 프로젝트 쓰기를 막는다. 선택 해석기가 없으면 영향받는 요소의 편집을 막는다. |
| 미래 Core·미지원 변환 | 호환 앱에서 작업한다. 기존 앱은 통합을 보류하고 양쪽 Git 이력을 보존한다. |

마이그레이션은 별도 worktree에서 검증한다. 이전 앱에서 실행한 작업의 통합이 `MIGRATION_MERGE_UNSUPPORTED`로 보류되면 원래 체크포인트를 유지하고, 대상 스키마를 지원하는 앱에서 현재 기준으로 새 작업을 만들어 변경을 다시 작성하고 검토한다. [마이그레이션과 호환성](MIGRATIONS.md).

## 백업과 복구

- **정본과 저장된 작업**을 보존하려면 앱에서 체크포인트를 만든 다음, 독립 프로젝트의 Git 루트에서 `git bundle create <백업-경로>/project.bundle --all`과 `git bundle verify <백업-경로>/project.bundle`을 실행한다. 원격에 보존할 브랜치도 사용자가 직접 선택한다. 일반 원격 clone에는 push된 refs만 있고, 로컬 작업 브랜치는 원격 clone에서 복원할 수 없다.
- **커밋 전 파일과 복구 기록**이 필요하면 서버와 작업 실행기를 종료한 뒤 프로젝트 전체(`.git` 포함)와 앱 데이터 전체를 함께 복사한다. 연결 worktree와 운영 기록은 경로가 연결돼 있으므로 전체 복사본은 기존과 같은 절대 경로에 되돌리는 편이 안전하다. 작업을 다른 경로로 옮길 때는 [등록 이전과 worktree 복구 절차](WORKSPACES.md)를 따른다.
- **Git 백업만 남았을 때**는 빈 경로에 복제한다. 먼저 `git clone <백업-경로>/project.bundle <복원-경로>`로 정본을 열고, `git branch -r --list '*/workbench/task/*'`로 함께 복제된 작업 참조를 확인한다. 새 앱 데이터에서 프로젝트를 등록한 뒤 **프로젝트 관리**에서 해당 체크포인트를 골라 새 실행으로 재개한다. [체크포인트 재개](RESUME_AND_TOOLS.md).
- **색인만 손상됐을 때**는 먼저 앱의 재구축으로 확인한다. 앱을 종료한 상태에서 앱 데이터의 `caches`만 다른 위치로 옮기면 이후 조회가 Git·작업 파일에서 새 색인을 만든다. `runs`, `worktrees`, `integrations` 및 복구 journal이 있는 디렉터리는 보존한다. [색인 운영과 재구축](INDEXING.md).
- **승인 통합 또는 저장이 중단됐을 때**는 현재 파일을 복사해 보존하고 앱을 다시 시작한다. 승인 통합 복구에서 검토한 적용을 완료하거나 중단 전으로 복원할 수 있다. 앱이 외부 편집을 발견하면 현재 파일을 유지한다. 보존된 후보와 현재 파일을 비교하고 어떤 변경을 살릴지 확인한 후 다시 검토한다. 외부 작업의 결과가 불명이면 같은 요청을 다시 보내기 전에 상태를 조회한다. [수동 작업과 통합 복구](MANUAL_WORKFLOW.md), [외부 작업 재개](RESUME_AND_TOOLS.md).
